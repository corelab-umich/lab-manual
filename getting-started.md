# Getting started

## Choose the right project and build

Identify the platform, hardware revision, installed software versions, and most recent experiment before following any instructions. Each project's hardware and software pages provide places to capture those details.

## Capture knowledge where it belongs

- Put procedures and small explanatory diagrams in this repository.
- Record exact version numbers and code commit IDs alongside setup instructions.
- Keep raw datasets and large CAD/media assets in approved shared storage; record stable locations and access requirements here.
- Do not commit credentials, personal access tokens, private network details, or data that the lab has not approved for sharing.

## Local editing

Pages are Markdown files. Change a page in a text editor, run the local build from the workspace README, and inspect the preview. Before a remote exists, use local Git to track changes; afterward, use branches and pull requests for review.

## First contribution

Recover one old build note, identify its author and applicable revision, and migrate it using the [handoff template]({{ '/templates/#student-handoff' | relative_url }}). A clearly labeled incomplete note is useful; an apparently authoritative procedure with missing context is not.
